# Руководство администратора (дипломный проект «Businka»)

## Введение

Данное руководство предназначено для администратора информационной системы интернет-магазина украшений «Businka», разработанной на PHP-фреймворке Yii2 и СУБД MySQL.

**Область применения:** обслуживание, поддержка работоспособности и эксплуатация функционала администрирования сайта.

**Краткое описание возможностей админ-панели:**
- вход в админ-панель по учетной записи администратора;
- управление заказами: просмотр и изменение статуса заказа;
- управление товарами: редактирование карточек, изменение остатка на складе и статуса активности;
- управление акциями: создание/редактирование/удаление акций, переключение активности, привязка товаров к акции;
- модерация отзывов: одобрение, отклонение, удаление.

**Уровень подготовки пользователя:** базовые навыки работы с веб-приложениями и панелями администрирования (знание адресной строки, умение искать ошибки в журнале/логе), понимание роли администратора и принципов работы с БД.

## Назначение и условия применения

### Назначение

Руководство используется при выполнении администратора следующих видов деятельности:
- поддержка каталога и товарного наличия (изменение остатка и статуса активности);
- поддержка корректности бизнес-процессов заказов (смена статуса: `pending`, `processing`, `completed`, `cancelled`);
- управление маркетинговыми активностями (акции и их привязка к товарам);
- обеспечение качества контента (модерация отзывов пользователей);
- диагностирование и устранение типовых сбоев веб-приложения.

### Условия применения

Средство автоматизации (админ-панель) применяется при соблюдении условий:
1. Приложение развернуто на сервере и доступно пользователям по URL.
2. Настроено подключение к БД (см. раздел «Подготовка к работе»).
3. Администратор имеет доступ к учетной записи с ролью `admin`.
4. Имеется доступ к журналам/логам веб-сервера (и, при необходимости, к логам Yii2).
5. Для выполнения действий, влияющих на данные (остатки, статусы, модерация), активируется корректная CSRF-защита и разрешены требуемые HTTP-методы.

## Подготовка к работе

### Ссылка на GitHub

Укажите здесь ссылку на ваш репозиторий GitHub:
`https://github.com/<username>/<repo>`

### Требования к окружению

- PHP версии **не ниже 7.4**.
- MySQL (подключение указывается в конфигурации приложения).
- Установленный Composer для установки зависимостей Yii2.
- Веб-сервер (Apache/Nginx/IIS) с поддержкой PHP.

### Развертывание приложения на сервере (общая схема)

1. **Установка зависимостей**
   - Выполните в корневой директории проекта:
     - `composer install`
2. **Настройка подключения к базе данных**
   - Отредактируйте файл `config/db.php`:
     - DSN, имя пользователя и пароль БД.
   - Значения должны соответствовать вашей СУБД и созданной базе данных.
3. **Настройка ключей приложения**
   - В `config/web.php` установите секретный `cookieValidationKey` (не оставляйте тестовое/учебное значение).
4. **Применение миграций**
   - Если таблицы не созданы, выполните миграции:
     - `php vendor/bin/yii migrate`
   - В проекте предусмотрена миграция добавления полей приветственной скидки для заказов.
5. **Права на файловые директории**
   - Убедитесь, что веб-пользователь/пользователь веб-сервера имеет права на:
     - `runtime/`
     - `web/assets/`
6. **Проверка работоспособности**
   - Откройте в браузере:
     - главную страницу сайта (например, `/site/index` или корневой `/`);
     - доступность каталога товаров;
     - страницу входа в админ-панель: `/admin/login`.

## Описание операций

Ниже описаны основные операции администратора, доступные в рамках реализованного функционала админ-панели.

### 1) Вход в админ-панель

1. Откройте URL: `/admin/login`
2. Введите:
   - `email`
   - `password`
   - при необходимости отметьте «Запомнить меня».
3. После входа доступ будет разрешен **только** пользователю с ролью администратора (`is_admin === 'admin'`).

Если учетная запись не имеет админ-прав, вход будет отклонен сообщением о недоступности админ-панели.

### 2) Дашборд администратора

Страница: `/admin/index`

На дашборде отображаются сводные показатели:
- заказы сегодня;
- общее число заказов;
- общее число товаров;
- товары с малым остатком;
- общее число пользователей;
- число активных акций.

Также доступны блоки:
- «Последние заказы» (с переходом на управление заказами);
- «Товары с малым остатком» (с быстрым редактированием количества).

### 3) Управление заказами

Страница списка: `/admin/orders`

Операции:
1. **Просмотр заказа**
   - Откройте страницу просмотра через кнопку «Просмотр».
   - В карточке заказа отображаются:
     - номер заказа, дата, текущий статус;
     - ФИО/телефон/email клиента;
     - адрес доставки и комментарий (если заполнены);
     - список позиций заказа (товар, цена, количество, сумма по позиции).
2. **Подтверждение/изменение статуса заказа**
   - На странице заказа используется модальное окно «Изменение статуса».
   - Доступные статусы (по модели заказа):
     - `pending` — «Ожидает обработки»
     - `processing` — «В обработке»
     - `completed` — «Выполнен»
     - `cancelled` — «Отменен»
   - Для сохранения нажмите «Сохранить».
3. Изменение статуса выполняется с использованием AJAX-запроса, при успешном сохранении статус обновляется на клиентской стороне.

### 4) Управление товарами и складским остатком

Страница: `/admin/products`

Операции:
1. **Фильтрация товаров**
   - Поиск/фильтры включают:
     - название товара;
     - категорию;
     - статус активности (`Активные/Неактивные`);
     - признак скидки;
     - диапазон остатка (0/1-5/5-10/10+).
2. **Изменение количества на складе**
   - Нажмите на бейдж остатка (количество) в таблице.
   - Заполните новое значение в модальном окне.
   - Нажмите «Сохранить».
   - Количество обновляется через AJAX (`/admin/quick-update-quantity`).
3. **Переключение статуса активности товара**
   - Нажмите на бейдж статуса (например, «Активен/Неактивен»).
   - Действие отправляется через AJAX (`/admin/toggle-product-status`).
4. **Редактирование карточки товара**
   - Нажмите «Редактировать» в строке товара.
   - Редактирование выполняется на странице `/admin/update-product` (по `id` товара).
5. **Добавление нового товара**
   - В админ-интерфейсе предусмотрена кнопка «Добавить товар», которая ведет к форме создания по маршруту `/product/create`.
   - Заполните обязательные поля и сохраните карточку.

#### Редактирование товара (возможные поля)

На форме редактирования предусмотрены:
- название, описание;
- цена, количество;
- выбор категории;
- переключатели:
  - `is_active` (активен/неактивен);
  - `is_discount` (скидка);
- при скидке задается `old_price`;
- загрузка изображения товара;
- опционально — привязка к акциям (если предусмотрена в модели/форме).

### 5) Управление скидками и акциями

Раздел акций: `/admin-promo/index`

Операции:
1. **Создание акции** — переход по кнопке «Создать акцию»:
   - маршрут `/admin-promo/create`
2. **Редактирование акции** — кнопка «Редактировать»:
   - маршрут `/admin-promo/update`
3. **Удаление акции** — кнопка «Удалить» (с подтверждением).
4. **Переключение активности акции**:
   - в таблице по кнопке «Активно/Неактивно» (POST).

Поля формы акции включают:
- `title` (название)
- `description` (описание)
- `discount_percent` (скидка в %)
- `conditions` (условия)
- `start_date` и `end_date` (даты начала/окончания)
- `sort_order` (порядок сортировки)
- `is_active` (активность)
- загрузка изображения акции
- выбор `product_ids` (товары, участвующие в акции).

После изменения акции система автоматически применяет/отменяет скидки для связанных товаров.

### 6) Модерация отзывов

Страница: `/admin/reviews`

Операции:
1. **Фильтры**:
   - товар, пользователь, рейтинг, статус модерации (`Одобренные/На модерации`), дата создания.
2. **Одобрение отзыва**
   - кнопка «✓ Одобрить».
   - отзыв становится видимым публичным пользователям.
3. **Отклонение отзыва**
   - кнопка «✗ Отклонить».
   - отзыв возвращается в состояние «на модерации».
4. **Удаление отзыва**
   - кнопка «🗑 Удалить».
   - отзыв удаляется из базы данных.

Операции выполняются через AJAX и подтверждаются обновлением списка/уведомлением.

## Аварийные ситуации

Ниже приведены типовые неисправности и способы их устранения.

### 1) Ошибка 500

**Признаки:** вместо страницы отображается сообщение об ошибке, код ответа сервера — `500`.

**Возможные причины:** исключение в коде PHP, неверная конфигурация, ошибки подключения к БД, проблемы с доступом к файлам и т.п.

**Порядок действий:**
1. Проверьте логи приложения и веб-сервера:
   - лог ошибок PHP/web-сервера;
   - файл логов Yii2 (в `runtime/`).
2. Для временного анализа включите вывод технической информации:
   - в `php.ini` установите:
     - `display_errors = On`
   - при необходимости включите режим отладки в `web/index.php`:
     - `YII_DEBUG` должен быть `true`, а `YII_ENV` — `dev`.
   - В проекте техническое сообщение отображается в `views/site/error.php` только при `YII_DEBUG` и если ошибка не 404.
3. После устранения причины обязательно верните настройки безопасности:
   - переключите приложение в продакшн (см. раздел «Как переключиться из режима отладки в продакшн» ниже);
   - установите `display_errors = Off` в `php.ini`.

### 2) Приложение потеряло работоспособность

**Порядок действий:**
1. Проверить доступность базы данных (см. сценарий «Ошибка подключения к базе данных»).
2. Проверить PHP-расширения и версии (минимум PHP 7.4).
3. Убедиться, что зависимости установлены:
   - `composer install` (при необходимости).
4. Перезапустить веб-сервер и обработчик PHP.
5. При подозрении на проблему с кешем:
   - очистить `runtime/` (без удаления базовых конфигураций).

Если ошибка связана с режимом отладки, отключите его и перезапустите приложение.

### 3) Утерян или скомпрометирован пароль администратора

**Цель:** восстановить управляемость системой и исключить повторное использование скомпрометированных учетных данных.

**Действия:**
1. Если доступ к серверу/БД есть:
   - создать нового администратора (или восстановить существующего) и назначить роль `is_admin = 'admin'`;
   - установить новый `password_hash` (вместо старого пароля).
2. Если вы не можете сгенерировать `password_hash` безопасно:
   - создайте новый аккаунт через форму регистрации пользователя;
   - затем назначьте ему роль администратора в БД.
3. Завершите активные сессии:
   - администратору выполнить выход из системы;
   - при необходимости очистить сессии на сервере.

### 4) Администратор уволился

Чтобы предотвратить неконтролируемое изменение данных:
1. Назначьте нового администратора (роль `admin`) и проверьте его доступ.
2. Для уволенного пользователя:
   - отключите роль `admin` (установите `is_admin = 'user'`);
   - при необходимости переведите статус пользователя в неактивный.
3. Проверьте, что критические операции (статусы заказов, остатки, акции, модерация) выполняются новым администратором.

### 5) Ошибка подключения к базе данных

**Признаки:** страницы не загружаются, ошибки в логах связаны с `db` компонентом.

**Действия:**
1. Проверьте файл `config/db.php`:
   - host, имя базы, имя пользователя, пароль.
2. Проверьте доступность MySQL из сети сервера (если это хостинг).
3. Убедитесь, что база существует и выполнены миграции (`yii migrate`).
4. При необходимости восстановите резервную копию БД и конфигурационных данных.

### 6) Сайт работает медленно

**Действия:**
1. Проверьте нагрузку на сервер:
   - CPU, RAM, дисковое пространство, состояние MySQL.
2. Проверьте медленные запросы в MySQL (если доступно).
3. Убедитесь, что не включены лишние режимы отладки на продакшн.
4. При необходимости включите оптимизации уровня Yii/БД (например, кэширование схемы в MySQL/Yii — зависит от требований проекта).
5. Проверьте количество и размер изображений:
   - при необходимости проверьте правильность хранения `web/images/`.

## Как переключиться из режима отладки в режим продакшн

В текущем проекте в `web/index.php` указано:
- `YII_DEBUG` и `YII_ENV` задаются строками в начале файла.

Для перехода в продакшн:
1. Откройте `web/index.php`.
2. Закомментируйте/удалите две строки, которые включают `YII_DEBUG = true` и `YII_ENV = 'dev'`.
3. Перезапустите веб-сервер и PHP.
4. Убедитесь, что:
   - в `views/site/error.php` не показываются отладочные детали (при `YII_DEBUG = false`);
   - `php.ini` не выводит ошибки пользователю (`display_errors = Off`).

## Рекомендации по освоению

Чтобы эффективно обслуживать приложение на сервере, администратору рекомендуется:
1. Освоить панель управления веб-сервером (например, cPanel/ISPmanager или интерфейс управления сервисами):
   - настройка виртуальных хостов (домен/поддомен, DocumentRoot);
   - управление PHP-версией и обработчиком (PHP-FPM/CGI);
   - настройка SSL-сертификатов и редиректов;
   - просмотр журналов (`error.log`, `access.log`) и их фильтрация по времени.
2. Регулярно проверять работоспособность:
   - доступность главных страниц и админ-панели;
   - отсутствие ошибок в логах после обновлений.
3. Настроить резервное копирование:
   - регулярные дампы MySQL;
   - копирование загруженных файлов (`web/images/`) и критичных конфигураций.
4. Использовать тестовую среду:
   - перед изменениями в продакшн проверять действия на тестовом сервере/в тестовом домене.
5. При инцидентах придерживаться общего алгоритма:
   - обнаружение (что сломалось);
   - локализация (логи, статус кодов);
   - устранение причины;
   - перевод в безопасный продакшн-режим;
   - проверка результата.
